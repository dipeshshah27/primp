# static-html

A two-page site in plain HTML, CSS and JavaScript. There is no framework, no build step, no dependencies and no live reload. reglet's tests put the proxy in front of it to check response encodings, conditional requests and source lookup when the only "source map" is the HTML file itself.

It is a standalone project, outside the pnpm workspace. Nothing needs installing.

```sh
PORT=4173 pnpm dev      # node server.mjs; binds to localhost
PORT=0 node server.mjs  # free port; prints "static-html fixture listening on http://localhost:<port>"
pnpm smoke              # starts the server on a free port, runs 24 HTTP checks, stops it
pnpm labels             # regenerate labels.json after editing markup
pnpm labels:check       # exit 1 if labels.json is stale
```

`HOST` overrides the bind address (default `localhost`). The default port is 4173.

## Pages

| Path | File | What is on it |
|---|---|---|
| `/` | `index.html` | Header with a menu button, hero, three cards, an order estimate (a number input and an `<output>`), footer. 38 labelled elements. |
| `/about.html` | `about.html` | The same header and footer, a heading, an ordered list, and a figure whose image has `width` and `height` set. 23 labelled elements. |

Other files: `css/site.css` (the only stylesheet), `js/site.js` (the only script, loaded with `defer`), `img/mark.svg`, `img/bench.svg`.

There is no `/about` without the extension; it is a 404. The 404 response is a small HTML page.

## Styles and script

`css/site.css` has one `@media (max-width: 640px)` block (single-column cards, the nav collapses behind the menu button, smaller headings), one `@media (prefers-reduced-motion: reduce)` block, and `:hover` rules on links, nav links, the menu button, `.button` and `.card`.

`js/site.js` does two things: the menu button toggles the class `is-open` on the nav and its own `aria-expanded`, and the estimate recalculates on input (14 EUR per notebook, 15% off from ten). It sets `data-js="ready"` on `<html>` when it has run. It only changes attributes, classes and text of elements that are already in the HTML, and the initial HTML already shows the values the script computes, so loading the script moves nothing.

Measured on 2026-11-20 in headless Chromium at 1280 px and 480 px wide: zero `layout-shift` entries on both pages.

## server.mjs

Node built-ins only. `GET` and `HEAD`; anything else is 405 with `Allow: GET, HEAD`.

| Behaviour | Detail |
|---|---|
| Content types | `.html` `text/html; charset=utf-8`, `.css` `text/css; charset=utf-8`, `.js` `text/javascript; charset=utf-8`, `.json` `application/json; charset=utf-8`, `.svg` `image/svg+xml`, plus png, jpg, webp, ico, woff2, txt, md |
| gzip | Sent when `Accept-Encoding` allows gzip (q-values are honoured), for html, css, js, json, svg, txt and md. The gzip response is streamed: `Transfer-Encoding: chunked`, no `Content-Length`. `index.html` is 3924 bytes plain and 1219 bytes gzipped. |
| Identity | Without gzip the response has `Content-Length`. A proxy that injects into the HTML has to correct or drop it. |
| `Vary` | `Accept-Encoding` on every compressible file, including the 304. |
| Validators | A weak `ETag` (`W/"<size>-<mtime ms>"`, both hex) and `Last-Modified` on every file. The gzip and identity responses share the ETag. |
| 304 | For `If-None-Match` with the current ETag, or `If-Modified-Since` at or after the file's modification time. `If-None-Match` wins when both are sent. |
| Caching | `Cache-Control: no-cache`, so a browser revalidates on every load. After a file is edited the next request gets 200 with the new content (measured: 304, 304, then 200 after an edit to `site.css`). |
| Not served | Dotfiles, `node_modules`, and anything outside this directory: 404. |

`Last-Modified` has one-second resolution. A client that revalidates with `If-Modified-Since` alone can get a 304 for a file edited twice within the same second; the ETag does not have that problem.

There is no live reload: a browser shows an edit only after it reloads the page.

`server.mjs` also exports `createStaticServer({ root })`, `acceptsGzip`, `etagOf`, `isNotModified` and `resolveFile` for tests that want the server in-process.

## labels.json

Ground truth for source lookup: 61 entries, generated by `scripts/gen-labels.mjs` from the `data-label` attributes in the `.html` files.

```json
{"label":"about-step-thread","file":"about.html","line":41,"col":73,"tag":"strong","kind":"static","page":"/about.html"}
```

- `file` is relative to this directory. `line` and `col` are 1-based and point at the `<` of the opening tag. Indentation is two spaces.
- `kind` is always `static`.
- `page` is the URL path that serves the file.
- Labels are unique across the site, so the shared header and footer have an `about-` prefix on the second page.

Some cases are there on purpose: opening tags that span several lines (`menu-toggle`, `estimate-input`), void elements (`brand-mark`, `estimate-input`, `about-figure-image`), and inline elements that start in the middle of a line (`hero-emphasis`, `about-step-thread`).

The generator has its own small tokenizer so that the fixture stays dependency-free. Its positions were compared once with parse5's `sourceCodeLocationInfo` (2026-11-20): 61 of 61 agree on file, line, column and tag.
