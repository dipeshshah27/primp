# sveltekit-svelte-5

A small SvelteKit 3.4 app on Svelte 5.58 (runes mode) and the Vite 8 dev server. reglet's tests put the proxy in front of it to check hot reload, streaming, form posts, cookies and Svelte source lookup.

It is a standalone project, outside the pnpm workspace.

```sh
pnpm install --ignore-workspace   # once, inside this directory
PORT=5173 pnpm dev                # binds to localhost; a busy port is an error, not a silent move
pnpm smoke                        # starts the dev server on a free port, runs 23 HTTP checks, stops it
pnpm labels                       # regenerate labels.json after editing markup
pnpm labels:check                 # exit 1 if labels.json is stale
```

`HOST` overrides the bind address (default `localhost`).

## Pages

| Path | What it is for |
|---|---|
| `/` | Header, hero, three feature cards, a panel with a `$state` counter, and the sign-in form. After signing in, the form is replaced by an account card with a sign-out button. |
| `/about` | A second hydrated page with an `{#each}` list, for client-side navigation. |
| `/streamed` | The server `load` returns an un-awaited promise that resolves after 800 ms. The page shell arrives in the first chunk and the value in a later chunk of the same response (measured: shell at 3 ms, value at 803 ms). |
| `/server-only` | Sets `csr = false`. The response has no `<script>` at all, so nothing is hydrated, there is no hot reload on this page and its elements have no `__svelte_meta`. |
| `/api/me` | JSON `{ "user": string \| null }` read from the session cookie. Lets a test check the login without parsing HTML. |
| `/robots.txt` | A static file. |

Every page is wrapped by `src/routes/+layout.svelte` (header, `<main>`, footer) and by the template `src/app.html`.

## Components

`src/lib/components/`: `SiteHeader`, `SiteFooter`, `Hero`, `FeatureCard` (rendered three times), `Panel` (renders children passed by the page), `SignInForm`, `AccountCard`. Each has a scoped `<style>` block; all but `Panel` include an `@media (max-width: 640px)` rule, and several have `:hover` rules. Global tokens are in `src/app.css`.

## Sign-in, cookie and the Origin rule

The form posts to the action `/?/signin` in `src/routes/+page.server.ts`. On success the action sets the cookie `reglet_fixture_user=<name>` (`HttpOnly`, `SameSite=Lax`, `Path=/`, one day) and redirects with 303 to `/`. `/?/signout` deletes it. An empty name returns 400 and re-renders the form with an error.

Both forms use `use:enhance`. With JavaScript the browser posts with `fetch` and gets JSON back (`{"type":"redirect",...}`, status 200); without it, or when the request's `Accept` prefers `text/html`, the answer is the 303.

**The Origin check is on, and it is implemented by the fixture.** SvelteKit rejects a form `POST`/`PUT`/`PATCH`/`DELETE` whose `Origin` header is not the app's own origin, but SvelteKit 3 skips that check under `vite dev` (in `runtime/server/respond.js` it sits inside `if (!__SVELTEKIT_DEV__)`). So `src/hooks.server.ts` applies the same rule with the same status and message, and adds the response header `x-fixture-origin-check: rejected` so a test can tell who refused the request.

The app's own origin is `event.url.origin`, which in dev is `http://` plus the request's `Host` header. A proxy therefore has two ways to make a browser's form post succeed: forward the browser's `Host` unchanged, or rewrite `Origin` to the upstream origin. A request with no `Origin` header, or with the proxy's port in `Origin` and the upstream port in `Host`, gets 403.

## labels.json

Ground truth for source lookup: 51 entries, generated by `scripts/gen-labels.mjs` from the `data-label` attributes in `src/**/*.svelte` and `src/app.html`. Positions come from the Svelte compiler's parser.

```json
{"label":"feature-card","file":"src/lib/components/FeatureCard.svelte","line":8,"col":1,"tag":"li","kind":"client","page":"/","instances":3}
```

- `file` is relative to this directory. `line` and `col` are 1-based and point at the `<` of the opening tag. The sources are indented with tabs and a tab counts as one column.
- `kind`: `client` for elements of hydrated components (47), `server` for the three elements of `/server-only`, `static` for the one element in `src/app.html` (`app-shell`).
- `page`: a path where the element is rendered. `everyPage: true` marks layout and template elements, which are on every page; on `/server-only` those are not hydrated either.
- `instances`: present when the element is rendered more than once on its page.
- `when`: `signed-out` or `signed-in` for elements that exist in only one session state. A fresh browser is signed out.

Labels are never placed inside `{#if}`, `{#await}`, `{#key}` or `{#snippet}`; the generator refuses them. The await branches on `/streamed` use `id="streamed-value"` and `data-state` instead.

A fresh, signed-out load renders 34 labels (40 nodes) on `/`, 19 (21) on `/about`, 16 on `/streamed` and 16 on `/server-only`. `pnpm smoke` checks these counts against the HTML the server sends.

In the browser, every hydrated labelled element has `element.__svelte_meta.loc = { file, line, column }` with `file` relative to this directory and a 0-based `column`, so `column + 1` equals `col`. Measured on 2026-11-20 with Chromium: 39 of 39 on `/`, 20 of 20 on `/about` and 15 of 15 on `/streamed` match labels.json exactly; `app-shell` and all 16 nodes on `/server-only` have no `__svelte_meta`. `panel-body`, `measure-count` and `measure-button` are written in `+page.svelte` and rendered inside `Panel.svelte`; their `loc` points at `+page.svelte`.

## Things a test should know

- **TypeScript 6 is a dependency on purpose.** SvelteKit 3.4 imports `typescript` if it can find one and refuses to start on TypeScript 7 (`typescript_compiler_api_missing`). Without a local copy, Node finds the repo root's TypeScript 7 by walking up the directories, including from a copy under the repo's `.tmp/`.
- **Copies can share `node_modules` by symlink.** `vite.config.js` allows the real path of `node_modules` in `server.fs.allow` and keeps Vite's cache in `./.vite` next to the config, not in `node_modules/.vite`. SvelteKit still writes `node_modules/$app/` (generated tsconfig and types) into the shared install; that only affects type checking.
- The hot-reload WebSocket is opened on the page's own origin with a token: `ws://<host>/?token=...`.
- In dev the HTML has the CSS inlined in `<style data-sveltekit>` and no `charset` in `content-type` (`text/html`).
- The dev server prints one line per request (`200 GET /`).
